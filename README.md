## Overview

WATCHLOG is a C++20 security log analysis project that processes authentication events, normalizes event data, and explores rule-based detection of suspicious behavior.

The project focuses on modular design, structured event processing, testable detection logic, and extensibility. It is an experimental and educational project—not a production SIEM or EDR.

## Features

- Authentication event parsing and structured representation.
- Event classification and severity fields.
- Rule-based detection, including password-spray scenarios (implemented scope).
- Modular detection engine.
- Automated tests with GoogleTest.

## Event schema

| Field | Description |
|---|---|
| `timestamp` | Event timestamp |
| `hostname` | Host associated with the event |
| `source` | Source or log origin |
| `event_type` | Event category |
| `severity` | Event severity |
| `source_ip` | Source IP, when available |
| `source_port` | Source port, when available |
| `username` | Associated account, when available |

Fields may be optional depending on the input source.

## Detection focus

### Password spray

Password spraying attempts a limited set of passwords across multiple accounts. WATCHLOG's implemented detection logic is intended to flag patterns matching its configured/defined criteria.

See [Detection logic](docs/detection-logic.md) and [Test scenarios](docs/test-scenarios.md).

> Detection behavior is limited to the rules and input formats currently implemented. This documentation does not imply production monitoring or comprehensive threat coverage.

## Build

### Prerequisites

A C++20 compiler, CMake, Ninja, and project dependencies are required.

### Clone and configure

```bash
git clone https://github.com/arvres/WatchLog.git
cd WatchLog
cmake -S . -B build -G Ninja
cmake --build build
```

### Run

For the Windows/Git Bash build layout used during development:

```bash
./build/engine/WATCHLOG.exe
```

Adjust the executable path if the target or build layout changes.

## Tests

If tests are registered with CTest in the CMake project:

```bash
ctest --test-dir build --output-on-failure
```

Otherwise, run the test executable generated by the project. See [Test scenarios](docs/test-scenarios.md).

## Scope and disclaimer

WATCHLOG is an educational and experimental project. It is not intended to replace production SIEM, EDR, or SOC monitoring systems. Detection results require context and validation.
